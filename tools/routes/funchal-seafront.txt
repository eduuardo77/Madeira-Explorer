# A seafront walk, Funchal — the ordinary case
#
# `lat lon`, one point per line. Fed to the emulator by
# `bash tools/replay-route.sh` — which swaps them into the lon-lat order
# `adb emu geo fix` wants.
#
# ⚠ APPROXIMATE, AND FOR TESTING ONLY. These are hand-plotted to be plausible
# rather than surveyed: the job is to give the recorder a moving position and
# the map a line to draw. **Nothing here is content.** The curated places live
# in `content/pois.json` and are the project lead's (T-066), and no threshold
# may be tuned against a route that was invented.
#
#
# ⚠ MOVED 245 m NORTH ON 2026-08-14, BECAUSE IT WAS IN THE SEA.
# Every point here was about a quarter of a kilometre offshore, so the app drew
# the trace across open water — and the project lead reasonably read that as the
# highlighted line being wrong. It was not: the app drew exactly what this file
# fed it. Nothing was detectable while the map was a plain style with no
# coastline worth trusting; switching to Google's cartography made it obvious,
# which is the argument for looking at the screen rather than at the numbers.
#
# The shape was right and only the latitude was wrong, so the whole route moved
# by one constant. That constant is not a guess: `content/pois.json` puts Forte
# de São Tiago — which stands on the seafront — at 32.64672, and this route
# passed 275 m south of it; the Teatro Municipal agreed within 10 m over the
# 1.2 km between them. Two independent anchors giving the same offset is what
# makes a uniform shift the right correction rather than a fudge.
#
# It is still approximate and still not content.
#
# Walking pace, continuous signal, no gaps. This is the route that should
# produce an unbroken trace: if `traceGeoJson` breaks this into segments,
# something is wrong with the gap threshold rather than with the data.
